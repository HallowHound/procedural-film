# Living World project specification

## Brief and explicit assumptions
Theme, desired feeling, intended audience/use, duration, output dimensions/FPS,
video/wallpaper/dual mode, music ownership, reference rights and exclusions.
State whether long holds on a small number of vistas are acceptable.

## Art bible
Palette (named hex colours); materials/line language; light progression;
background/middle/foreground proportions; camera constraints; character scale;
contrast at night; static-frame composition target; visual mistakes to avoid.

## Event contract
For each event: participants, start condition, location/resource, preparation,
action duration, transition poses, completion condition, resulting state and
what other actors do. No simultaneous incompatible use of a prop/location.

## Time and repeat contract
Episode length; action speeds/durations independent of episode length; seed
namespaces; loop policy and period; persistent state vs derived state; expected
variations; how repeated chapters remain coherent. List what is NOT generated.

## Environment layers
Shared wind/weather/light fields; cloud/water cycles; distant wildlife; foreground
motion; maximum active particle counts; wrap/occlusion locations; cache budget.

## Engineering / ownership
Module owners, shared APIs and geometry, target machine, resolution/FPS budgets,
export chunk size, resume policy, audio policy, supported and untested hosts.

## Verification evidence
Commands, runtimes and measured resolutions; state/pixel determinism; action
boundary clips; loop handoff; normal-speed review; cold/warm frame costs; export
resume/corruption/audio tests; native host results; actual soak duration.

## Critique log
Issue / priority / evidence frame or time / owning module / fix / new evidence.

## Delivery and known limits
Player, MP4, source, contact sheet, commands, license notices, unfinished features,
unsupported themes/hosts, visual limitations and next concrete improvement.
