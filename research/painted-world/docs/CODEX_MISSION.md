# Codex mission: one accepted painted-world slice

Use this as the first bounded production task, **not** a request to generate a
finished hour in one run. Read the project's applicable AGENTS.md first.

## Mission prompt

Build a 60–90-second asset-first, painterly fantasy journey slice using the decision
in `research/painted-world/docs/BLUEPRINT.md`. The required look is the user's
supplied landscape, not the diagnostic cutout study and not generic low-poly art.
Default output is 1920x1080, 30fps, 16:9; framing and export dimensions are inputs.

Preserve the original procedural-film and living-world examples. Work separately.
Use Godot for the staged 3D runtime and Blender/compatible tools for canonical
assets and rigs. First inventory actual tools, graphics hardware, image-generation
access, asset licenses and installed versions. Report unavailable capabilities;
do not invent model calls or replace a missing art tool with thousands of Canvas
drawing commands. Do not incur paid generation/render charges without an approved
budget. Keep all unapproved source/generated media out of public Git.

Read only the blueprint, current task contract and files you own. Do not ingest
all short-film scene files or launch a critic per shot. Keep one director/integrator.
Use Astra for the look/architecture and difficult review; delegate bounded import,
shader, data and test tasks to Sol where available. This routing is a workflow
proposal, not a requirement to fake a multi-agent run when tools are absent.

First deliver a new native-16:9 colour key and one actual rendered stage frame.
Lock camera, material language, cast silhouettes and lighting. Use generated art
as approved plates/textures/concepts; preserve geometry when making local edits.
Store asset IDs, hashes, origin/license and approval decisions. Never regenerate
an approved hero simply because a new scene begins.

After the still is accepted, deliver normal-speed motion: three recognizable
travellers walk a real path across a bridge; one stops, turns and interacts with
a seat or held prop; the camera makes a real translation exposing near-object
occlusion; the group resumes into a connected section. Use canonical rigged actors,
contact anchors and distance-based gait. A depth sheet, cutout pan, dissolve or
camera move over one flat image does not satisfy the 3D-traversal gate.

Build only the modules necessary for this slice. Compile deterministic schedules
before playback. No model calls, wall-clock dependencies or unseeded randomness in
rendering. Where stateful animation/physics/temporal rendering requires warm-up,
checkpoint or replay it explicitly and test cold chunk starts. Respect each
projection plate's camera envelope. Assert on unsupported camera/asset combinations.

Run technical tests first, then inspect matched-scale stills and short normal-speed
clips for composition, material specificity, cast integration and contact. Use
at most two local correction rounds for a task. Escalate repeated defects with
three evidence crops and a specific decision request, not more automatic critics.
Do not accept art because tests pass. Do not claim human approval that was not given.

Acceptance package: source project, dependency/toolchain manifest, asset registry,
approved still, real 60–90s clip, brief test report and explicit unresolved defects.
Demonstrate output aspect controls, a camera-envelope violation test, a cast/prop
continuity test, day/night test frames and one resumed chunk join. Do not start a
10-minute or one-hour export before this slice is accepted. Stop at this gate with
evidence; new chapters are a separate authorized task.

## Asset-generation briefs (templates, not executed tool calls)

### Composition / colour key

Create a newly composed 16:9 painterly fantasy landscape using the supplied image
as a visual-language reference: monumental distant citadel, atmospheric cliff depth,
rich green valley, small timber-and-stone inn, bridge and flowing stream, clustered
flowers, three readable but small travellers. Preserve quiet panoramic observation.
Avoid generic low-poly shapes, glossy game materials, uniform noise, UI, captions
or oversized foreground heroes. Compose for the agreed blockout camera and reserve
overscan for its actual path. Do not stretch the portrait reference into landscape.

### Layer or surface edit

Given the approved colour key, exact region mask and camera/depth guide, change
ONLY [specified surface/region]. Preserve all architecture, path geometry, horizon,
scale, lighting direction and locked cast. Produce a clean plate behind the moving
object where requested; a transparent silhouette alone is insufficient. Save the
new version separately and compare before/after alignment before approval.

### Canonical cast

Develop one consistent cast sheet from the approved character brief: front, side,
back and three-quarter views with matching proportions, wardrobe and equipment.
Neutral readable poses, no scene background. Make identities distinguishable by
silhouette and palette at small delivery size. This is a modelling reference,
not an animation sprite sheet and not proof of a ready-to-rig 3D asset. Approve the
same design before constructing meshes, skins, motion clips and prop attachments.

## Minimal director handoff

A task handoff contains: goal; owned files; locked asset IDs; relevant scene/rig
contract; at most three evidence images; required tests; correction limit; stop
condition. A task completion contains: changed files, commands actually run,
measurements, before/after evidence and remaining defects. Do not attach the whole
conversation or all unrelated artwork to every task.
